## 4. Fairness (customer_age, evaluation only)

Score used: blended, before graph uplift. Threshold: DECLINE at 850. BAF bands age by decade, so DESIGN's <25 / 25–50 / >50 are mapped to ≤20 / 30–50 / ≥60.

| age group | n | fraud rate | approval rate | decline rate | FPR @ decline | TPR @ decline |
|---|---|---|---|---|---|---|
| ≤20 | 51,437 | 0.644% | 85.62% | 0.021% | 0.014% | 1.21% |
| 30–50 | 145,471 | 1.504% | 76.07% | 0.093% | 0.052% | 2.83% |
| ≥60 | 8,103 | 4.430% | 61.77% | 0.432% | 0.271% | 3.90% |
| overall | 205,011 | 1.404% | 77.90% | 0.089% | 0.050% | 2.78% |

| disparity | value |
|---|---|
| approval-rate ratio, lowest / highest (≥60 / ≤20) | **0.7214** = 61.77% / 85.62% |
| four-fifths rule (≥ 0.80) | **NOT met** |
| FPR ratio, worst / best (≥60 / ≤20) | 19.8× |
| fraud-rate ratio ≥60 vs ≤20 | 6.9× (4.430% / 0.644%) |
| ≥60 group size | 8,103 = 3.95% of test set, so rates are noisy |

Mitigation status: **none implemented; disclosed, not fixed** (`docs/responsible-ai.md` §4.3). Plan, in order:

| # | step | status |
|---|---|---|
| 1 | per-segment threshold calibration or equalised-odds post-processing, disparity re-measured after | not done |
| 2 | proxy audit: check highest-gain features for age correlation, refit without the worst, measure accuracy cost | not done |
| 3 | fairness as a release gate: four-fifths ratio computed in CI on every retrain | not done |
| 4 | same evaluation for every other protected characteristic (BAF has only age) | not possible on this data |
| 5 | ongoing monitoring with alerts on disparity ratios | not done |

## 9. Similar cases (semantic layer)

Corpus: 41,858 case narratives at measurement time; MiniLM all-MiniLM-L6-v2, 384-dim, HNSW cosine. The narrative holds band, top reasons and graph signals; no identifiers, no raw score. Raw → centered measured on the same 41,858 rows; queries = 3,000 random labelled cases plus all 45 ring members.

| measure | raw | mean-centered (shipped) |
|---|---|---|
| cosine between two random cases, mean | 0.799 | 0.007 |
| cosine between two random cases, std | 0.084 | 0.358 |
| mean top-1 similarity | 0.9960 | 0.9795 |
| mean top-5 similarity | 0.9907 | 0.9524 |
| mean top-1 minus top-5 gap | 0.0053 | 0.0271 |
| fraud rate of neighbours, fraud-case queries | 40.9% | 41.7% |
| fraud rate of neighbours, legit-case queries | 5.2% | 5.2% |
| neighbours in the same band as the query | 100% | 100% |
| ring members with ≥1 ring member in top-5 (45 members, 225 slots) | 4 | 3 |
| same-ring hits | 0 | 0 |

| reading | value |
|---|---|
| ring-hit rate vs chance | centered 3/225 = 1.33% vs 0.11% = 12×; raw 1.78%, 16× |
| fraud rate by neighbour rank 1..5, raw | 9.4 / 8.8 / 8.7 / 8.7 / 8.9 % (flat) |
| fraud rate by neighbour rank 1..5, centered | 9.4 / 9.1 / 8.5 / 9.2 / 9.2 % (flat) |
| earlier "4.4× lift" (41.9% vs 9.6%) | **band effect, not embedding effect**: retrieval is same-band 100%, and a high-band case's neighbours are fraud-rich because the band is |
| live re-run on the current, larger corpus (includes stream decisions) | ring hits 3/225, same-band 92.0%, neighbours fraud 40.2% (72/179 labelled), band-matched baseline 51.1%, so 0.79× |

Say: similarity finds cases that look alike; the graph finds cases that are connected. Do not present cosine as a probability and do not claim fraud lift for it.
